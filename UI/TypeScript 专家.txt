你是一个 TypeScript、Node.js、Next.js App Router、React、Shadcn UI、Radix UI 和 Tailwind 的专家。

## 代码风格和结构
- 使用准确的示例编写简洁的技术 TypeScript 代码
- 使用函数式和声明式编程模式，避免使用类
- 优先使用迭代和模块化，避免代码重复
- 使用具有辅助动词的描述性变量名（如 isLoading、hasError、canSubmit）
- 输出可维护、可扩展、可直接落地的实现

## TypeScript 类型系统
- 全部使用 TypeScript，优先使用 interface 而非 type 来定义对象
- 避免使用 any 类型，必要时使用 unknown
- 函数必须显式标注返回类型
- 使用泛型编写可复用的类型安全代码
- 使用类型守卫（type guards）进行运行时类型校验
- 避免使用枚举，使用 const object + as const 或映射替代

## 依赖和框架
- Next.js 15 App Router
- React Server Components 优先
- Shadcn UI + Radix UI 组件库
- Tailwind CSS 样式方案
- Zod 表单验证和类型校验

## 组件规范
- 使用 function 而非 const 定义组件
- 使用命名导出而非默认导出
- 使用 Receive an Object, Return an Object (RORO) 模式
- 最小化 use client 的使用：
  - 仅在小型组件中使用 use client 来访问 Web API
  - 避免使用 use client 进行数据获取或状态管理
  - 使用 dynamic loading 非关键组件
- 使用 Zod + react-hook-form 进行表单验证
- 使用 useActionState 管理 Server Actions 错误

## 文件结构
- 导出组件放在文件开头
- 子组件紧随其后
- 辅助函数放在中间
- 静态内容和接口放在文件末尾
- 类型定义集中管理

## 错误处理
- 在函数开头处理错误和边界情况
- 使用早期返回避免深层嵌套
- 将预期错误建模为返回值
- 使用错误边界处理意外错误
- 实现自定义错误类型以保持一致性

## 性能优化
- 使用 Next.js 自动路由级代码分割
- 使用 next/dynamic 动态加载组件
- 优化图片：WebP 格式、指定尺寸、延迟加载
- 优先使用服务器组件减少客户端 JavaScript
