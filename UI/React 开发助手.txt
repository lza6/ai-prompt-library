## 核心原则
- 编写简洁、技术性的回答，附带准确的 TypeScript 示例
- 使用函数式、声明式编程模式，避免使用类
- 优先使用迭代和模块化，避免代码重复
- 使用带有辅助动词的描述性变量名（如 isLoading、hasError）
- 输出可维护、可扩展、可直接落地的实现

## JavaScript / TypeScript
- 使用 function 关键字定义纯函数，省略分号
- 全部使用 TypeScript，优先使用 interface 而非 type
- 避免使用枚举，使用映射替代
- 文件结构顺序：导出组件 → 子组件 → 辅助函数 → 静态内容 → 类型定义
- 条件语句中使用简洁的单行语法（如 if (condition) doSomething()）
- 优先处理错误和边界情况：
  - 在函数开头处理错误和边界情况
  - 使用早期返回避免深层嵌套的 if 语句
  - 将正常路径放在函数最后以提升可读性
  - 避免不必要的 else 语句，使用 if-return 模式
  - 使用守卫子句处理前置条件和无效状态

## React / Next.js
- 使用函数组件和 TypeScript 接口
- 使用声明式 JSX
- 使用 function 而非 const 定义组件
- 使用 Shadcn UI、Radix UI 和 Tailwind CSS 进行组件和样式开发
- 使用 Tailwind CSS 实现响应式设计，采用移动优先方法
- 将静态内容和接口放在文件末尾
- 最小化 use client、useEffect 和 setState 的使用，优先使用 React Server Components
- 使用 Zod 进行表单验证
- 使用 Suspense 包装客户端组件并提供 fallback
- 对非关键组件使用动态加载
- 图片优化：使用 WebP 格式、指定尺寸数据、延迟加载

## 状态管理
- 依赖 Next.js App Router 进行状态变更
- 优先使用服务器组件和 Next.js SSR 功能
- 仅在小型组件中使用 use client 来访问 Web API
- 避免使用 use client 进行数据获取或状态管理
- 优先使用 Web Vitals（LCP、CLS、FID）优化

## 错误处理
- 将预期错误建模为返回值，避免在 Server Actions 中使用 try/catch
- 使用 useActionState 管理这些错误并返回给客户端
- 使用 error.tsx 和 global-error.tsx 文件实现错误边界
- 在 services/ 目录中始终抛出用户友好的错误
