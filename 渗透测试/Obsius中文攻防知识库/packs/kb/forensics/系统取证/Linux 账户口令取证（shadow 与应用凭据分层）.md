# Linux 账户口令取证（shadow 与应用凭据分层）

镜像整体流程见 [[forensics/磁盘与内存/磁盘与内存镜像取证.md|磁盘与内存]]；浏览器、git、容器等应用层痕迹见 [[forensics/系统取证/Linux 与应用取证.md|Linux 与应用取证]]。

## 测试面

| # | 方向 | 判据（怎么发现） | 动作 |
|---|---|---|---|
| 1 | 系统账户口令 | `/etc/passwd` 里该用户 shell 不是 `nologin`/`false` | 取 `/etc/shadow`，按字段前缀定哈希类型（§1） |
| 2 | 哈希爆破 | shadow 字段以 `$id$` 开头且带 salt | 按 id 选 hashcat 模式，或纯 Python 逐条比对（§2） |
| 3 | 字典构造 | 题干附了字典，或检材内有自己的词表 | 先用给定字典，再补语境词与变形（§3） |
| 4 | 口令被禁用 | shadow 字段是 `*`、`!`、`!!` 或空 | 不要爆破，转明文残留（§5） |
| 5 | 明文残留 | 历史、安装日志、客户端配置里出现交互式口令 | 按 §5 清单逐处搜 |
| 6 | 应用连接串 | 配置文件里有 `scheme://user:pass@host/db`、`.env`、框架 secret | 只能证明应用侧凭据，别当系统口令（§6） |
| 7 | 应用库账号表 | 库文件里有用户表与口令列 | 先读应用初始化逻辑，再判是否可逆（§6.1） |

## 1. 取 shadow 并判定哈希类型与可用性

**前置**：能读到文件系统内容——镜像已按分区边界切出并能 `fls`/`icat`，或有 root 只读挂载。
**判据**：`/etc/passwd` 中目标用户的 shell 字段是可登录 shell；`/etc/shadow` 中同名条目第二字段非空。
**动作**：

```bash
mmls image.dd                       # 取根分区 Start / Length
fls -o <start> -r -p image.dd | grep -E '/etc/(passwd|shadow|login.defs)$'
icat -o <start> image.dd <shadow_inode>
```

**不成立**：目标字段是 `*`、`!`、`!!` 或空 → 该账户不靠口令登录，爆破无意义，转 §5。
**降级**：没有 Sleuth Kit 时先按分区边界切出分区镜像，再交给 `debugfs`：

```bash
dd if=image.dd of=part.img bs=512 skip=<start> count=<length>
debugfs -R 'cat /etc/shadow' part.img
```

`debugfs` 不能直接吃带分区表的整盘镜像，必须先切分区——这是它比 `fls -o` 麻烦的地方。

## 2. 按哈希前缀选爆破模式

**前置**：hashcat 或 john 可用；yescrypt（`$y$`）需要较新版本，老版本会直接报不支持。
**判据**：字段前缀决定模式——`$1$` md5crypt、`$5$` sha256crypt、`$6$` sha512crypt、`$y$` yescrypt。
**动作**：

```bash
unshadow passwd shadow > creds.txt
john --wordlist=words.txt creds.txt
hashcat -m 1800 hash.txt words.txt      # $6$ sha512crypt
```

**不成立**：字典跑满仍空 → 口令不在该字典路径上，回 §3 补语境词，或复核层级（§6）。
**降级**：只有 Python 时用 `crypt.crypt(候选, salt)` 逐条比对（支持 `$1$`/`$5$`/`$6$`；新版 Python 已移除该模块，改用 `passlib.hash`，或 `openssl passwd -6 -salt <salt> <候选>` 验单条）：

```python
import crypt
for w in open('words.txt').read().split():
    if crypt.crypt(w, field) == field:
        print('match', w); break
```

逐条比对只适用于候选集在字典量级；上百万候选必须换 hashcat，纯 Python 跑不动。

## 3. 字典与规则的最小可用构造

**前置**：已确认问的是 shadow 里的系统账户口令，且存在字典来源。
**判据**：题干显式附字典 → 先用它；检材内有词表或线索文件 → 优先于通用大字典。
**动作**：先跑给定字典（命中率最高、成本最低）；再补检材语境词——用户名、主机名、项目/赛事名，以及首字母大写加数字后缀的变形；最后才上通用大字典与规则。
**不成立**：给定字典无命中 → 答案多半不在这条路径上，回 §1 复核层级，而不是继续堆字典。
**降级**：没有 hashcat/john/`crypt` 时，用 `openssl passwd` 对每条候选生成同 salt 摘要比对；量大时先 `sort -u` 压缩候选集。

## 4. 口令被禁用时不要爆破

**前置**：已确认 shadow 字段为 `*`/`!`/空。
**判据**：`*` 或 `!` 开头表示口令被锁定，哈希不可用于验证任何候选；空字段表示无口令即可登录。
**动作**：判定「该账户无可用口令」，重新读题干——问的可能不是这个账户，或不是系统账户。
**不成立**：题干问的确实是该账户 → 答案落在明文残留，走 §5。
**降级**：检材里若有 `/etc/gshadow`、`/etc/security/opasswd`，可交叉确认该账户是否曾设置过口令。

## 5. 明文口令残留位置

**判据**：口令不进 shadow 的场合——安装时写进日志、脚本里显式传参、客户端配置里存明文。

| 位置 | 为什么会有 |
|---|---|
| `~/.bash_history`、`~/.zsh_history` | `ssh`/`mysql -p`/`su` 的交互历史 |
| `~/.my.cnf`、`~/.pgpass` | 客户端配置里的明文口令 |
| `/var/log/installer/`、`/var/log/cloud-init*` | 系统安装/初始化记录的参数 |
| `/etc/systemd/system/*.service` 的 `ExecStart=` | 服务用 `-p` 传口令 |
| `~/.config/autostart/`、显示管理器配置 | 自动登录相关脚本 |
| 桌面/文档目录下的脚本与便签 | 人工留下的口令 |

**动作**：按上表逐处搜 `grep -aiE 'passw|passwd|pwd|mysql .*-p'`，注意中文文件名与大小写。
**不成立**：全都没有 → 回 §1，shadow 爆破是唯一路径。
**降级**：文件已被删时，从空闲空间与日志残留再捞（见磁盘恢复手册）。

## 6. 应用连接串口令：不等于系统账户口令

**前置**：能读到应用目录与它的配置。
**判据**：配置里出现 `scheme://user:pass@host/db`、`.env` 的 `*_PASSWORD`、框架 `SECRET_KEY`——都是应用侧凭据。
**动作**：登记为线索，先确认题干问的是「系统账户登录口令」还是「应用/数据库口令」；两者答案不同。
**不成立**：题干明确问数据库口令或应用管理员口令时，它才是答案。
**降级**：层级无法确定时，两边候选都按候选线索登记并标清来源层级，交判定方按题目措辞裁决。

### 6.1 应用库里的账号表

**前置**：检材里有数据库文件（MySQL 的 `*.ibd`、SQLite 的 `.db`），且应用带初始化/建表逻辑。
**判据**：表里有用户名与口令列；口令列是弱散列（md5/sha1 无 salt）可爆破，是 bcrypt/argon2 且 salt 随机则几乎不可逆。
**动作**：先读应用的初始化代码（建库脚本、`init_db`、迁移与种子数据）——**种子口令常是硬编码的**，比逆哈希快一个数量级；再从库文件取账户行与口令列。
**不成立**：初始化逻辑显示口令随机生成且未落盘 → 该口令不可恢复，答案必在 §1 或 §5。
**降级**：库文件解析不动时，`strings` 直接搜表名与用户名；只有单表 `.ibd` 时需配合同版本的元数据/表结构才有意义。

## 7. 步骤清单与复现顺序

按序执行，任一步「不成立」就按该节给的方向跳转，不要并行堆手段：

1. 分区定位 → 取 `/etc/passwd`，判定目标用户是否可登录（§1）。
2. 取 `/etc/shadow`，**先看字段前缀与长度**，判定是否可用（§1、§4）。
3. 记下哈希类型与 salt 参数，选爆破模式（§2）。
4. 先跑题干给定字典，再补语境词（§3）。
5. 无命中 → 复核层级是否选错（§6），而不是加长字典。
6. 每步留一条可复现命令与输出片段，供复核。

## 8. 坑与适用条件

- **适用条件**：目标账户在 `/etc/passwd` 中存在且 shell 可登录；镜像文件系统完整可读。
- **坑 1（层级混淆）**：配置文件里的数据库连接串口令是最容易被当成「账户登录口令」提交的，它属于应用侧。
- **坑 2（前缀误读）**：把 `*`/`!` 当作哈希去爆破，浪费整轮时间；这类账户本就没有可用口令。
- **坑 3（工具缺失）**：`crypt` 模块在新版 Python 已被移除，脚本会直接 ImportError；改走 `passlib` 或 `openssl passwd`。
- **坑 4（迭代参数）**：高迭代的 sha512crypt/yescrypt 在 CPU 上极慢，纯 Python 逐条比对会卡死，必须换 GPU 工具或先缩小候选集。
- **坑 5（凭据可逆性）**：应用库里的随机 salt + bcrypt/argon2 口令不可逆，别在它上面耗时间，回去读初始化代码或明文残留。
