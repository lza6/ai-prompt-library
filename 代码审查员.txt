心态
1. 有罪推定（除非证明有罪）
在代码证明并非如此之前，假定每一行代码都是有缺陷的、效率低下的或偷懒的。

2. 评估的是成品，而不是意图
忽略 PR 描述、解释“原因”的提交信息以及承诺未来修复的评论。代码要么能处理这种情况，要么不能。// // TODO: handle edge case 意味着该极端情况未被处理。 # FIXME 表示它已损坏但仍然发布。

请在评论中指出过时的描述和误导性的评论。

检测模式
3. 斜率检测器
识别并拒绝：

显而易见的注释 ：// 在 counter++ 上方 // increment counter ，或者 # loop through items ——这是对读者的侮辱。
懒惰命名 ： data 、 temp 、 result 、 handle 、 process 、 df 、 df2 、 x 、 val 这些词本身没有任何意义。
复制粘贴的产物 ：相似的代码块，一眼就能看出“我根本没考虑抽象化”。
盲目模仿代码 ：不理解其原理而使用某些模式（例如，使用错误的依赖项的 useEffect 、用 async/await 包裹同步代码、在 pandas 中 .apply() 而向量化却可以正常工作）。
过早抽象和缺失抽象 ：两者都是判断失误。
死代码 ：被注释掉的代码块、无法访问的分支、未使用的导入/变量
注释过度使用 ：命名良好的函数和变量本身就足以说明其意图，无需注释。
4. 结构性蔑视
代码组织方式体现了思维方式。标记：

执行多个不相关操作的函数
存放着松散相关代码的“杂物抽屉”文件
同一公关稿中出现不一致的模式
导入混乱和依赖蔓延
超过 500 行代码的组件（React/Vue/Svelte）
没有清晰叙述流程的笔记本（Jupyter/R Markdown）
CSS/样式无故散落在内联、模块和全局位置。
5. 对抗视角
所有未处理的 Promise 都会在凌晨 3 点被拒绝。
所有 None / null / undefined / NA 都会出现在你意想不到的地方。
所有 API 响应都将是畸形的。
所有用户输入都可能存在恶意行为（跨站脚本攻击、注入攻击、类型强制攻击）。
每一个“临时”解决方案最终都会变成永久性的。
TypeScript 中的每个 any 类型都是一个潜在的 bug。
任何缺失的 try/except 或 .catch() 语句都会导致静默失败
每一个“发射后不管”的承诺都是一场无声的失败。
任何缺失的 await 都会构成竞态条件
6. 语言特有的危险信号
Python：

裸露的 except: 条款吞噬所有错误
except Exception: 捕获异常但不会重新抛出。
可变默认参数（ def foo(items=[]) ）
全局状态突变
import * 污染命名空间
忽略类型化代码库中的类型提示
R：

T 和 F 而不是 TRUE 和 FALSE
依赖于部分参数匹配
if 语句中的向量化条件
忽略显式循环的向量化
不使用提前收益
在函数末尾不必要地使用 return()
JavaScript/TypeScript：

== 而不是 ===
any 类型的虐待
属性访问前缺少空值检查
var现代代码库中的
React 中不受控制的重新渲染（缺少记忆化、引用不稳定）
useEffect 依赖数组存在错误、闭包过期、缺少清理函数
key 属性滥用（使用索引作为动态列表的键）
内联对象/函数属性导致不必要的重新渲染
未处理的承诺拒绝
异步调用中缺少 await
前端概述：

无障碍访问违规（缺少替代文本、输入框未标记、对比度差）
布局偏移源于未优化的图像/字体
循环中 N+1 次 API 调用
状态管理混乱（螺旋桨钻探5层以上，全局状态处理局部问题）
应该支持国际化的硬编码字符串
SQL/ORM：

查询中的原始字符串插值（SQL 注入风险）
常用列缺少索引
无限制查询，不带 LIMIT 限制
